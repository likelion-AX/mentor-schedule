# 교육자료 — 외부 에이전트 접근 가이드

멘토들이 올린 교육자료를 **별도 에이전트**가 가져가 읽고(요약·QC·중복점검), 결과를 다시 써넣기 위한 접근 방법입니다.
이 문서 하나를 에이전트 만드는 쪽에 그대로 넘기면 됩니다.

---

## 0. 준비 — 연결 정보

| 항목 | 값 |
|---|---|
| 프로젝트 URL | `https://uwuvrvwgylkirwuwzoux.supabase.co` |
| 인증 키 | **service_role 키** (Supabase → Project Settings → API → `service_role` `secret`) |

> ⚠️ **service_role 키는 모든 권한을 가진 비밀 키입니다.**
> - **서버/백엔드(에이전트)에서만** 쓰고, 절대 프론트엔드·깃·공개 장소에 넣지 마세요.
> - 이 키는 RLS(행 보안)를 우회하므로 **모든 멘토의 자료 전체**를 읽고 쓸 수 있습니다. (에이전트 용도에 적합)

요청 공통 헤더:
```
apikey: <service_role_key>
Authorization: Bearer <service_role_key>
```

## 1. 자료 목록 읽기 — `materials_export` 뷰

교육명·회차날짜·업로더까지 정리된 뷰입니다. 한 번에 다 가져옵니다.

```bash
curl "https://uwuvrvwgylkirwuwzoux.supabase.co/rest/v1/materials_export?select=*&order=program_client,week_no" \
  -H "apikey: $KEY" -H "Authorization: Bearer $KEY"
```

필터 예시 (PostgREST 문법):
- 특정 교육만: `?program_id=eq.<uuid>`
- 특정 회차만: `?program_id=eq.<uuid>&week_no=eq.2`
- 파일형만: `?kind=eq.file` / 링크형만: `?kind=eq.link`
- 아직 분석 안 한 것만: `?summary=eq.` (빈 요약)

### 응답 필드

| 필드 | 의미 |
|---|---|
| `id` | 자료 고유 ID (분석결과 쓸 때 사용) |
| `program_id` / `program_client` / `program_title` | 어느 교육 (코드 / 고객사 / 제목) |
| `week_no` / `session_date` | 몇 회차 (NULL=교육 공통) / 그 회차 날짜 |
| `kind` | **`file`**(업로드 파일) 또는 **`link`**(URL) |
| `title` / `description` | 제목 / 설명 |
| `file_path` | (kind=file) Storage 경로 → 아래 2번으로 다운로드 |
| `file_name` / `file_type` / `file_size` | 원본 파일명 / MIME / 바이트 |
| `link_url` | (kind=link) 그대로 열면 되는 URL |
| `uploader_name` | 올린 멘토 이름 |
| `summary` / `qc_result` / `tags` | **에이전트가 채울 분석 결과** (3번) |

> **정리 기준**: `program_id` → `week_no` 로 그룹핑하면 "교육 × 회차"별로 자료가 묶입니다.

## 2. 파일 내려받기 (kind=file)

`file_path` 를 그대로 붙여 service_role 로 GET 하면 파일 바이트가 옵니다 (비공개 버킷이지만 service_role 은 통과).

```bash
curl "https://uwuvrvwgylkirwuwzoux.supabase.co/storage/v1/object/materials/<file_path>" \
  -H "Authorization: Bearer $KEY" --output "<원하는파일명>"
```

- `file_name` 을 저장 파일명으로 쓰면 원본 한글 이름 그대로 보존됩니다.
- 링크형(kind=link)은 다운로드 없이 `link_url` 을 그대로 사용하세요.

## 3. 분석 결과 다시 써넣기

분석(요약·QC·태그)을 `materials` 테이블의 해당 행에 PATCH 합니다. (service_role 이라 바로 가능)

```bash
curl -X PATCH "https://uwuvrvwgylkirwuwzoux.supabase.co/rest/v1/materials?id=eq.<id>" \
  -H "apikey: $KEY" -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "summary": "한 줄 요약 ...",
    "qc_result": { "score": 82, "issues": ["..."] },
    "tags": ["리더십", "비전공자"]
  }'
```

| 쓸 컬럼 | 용도 |
|---|---|
| `summary` (text) | 자동 요약 |
| `qc_result` (jsonb) | QC 점검 결과(점수·지적사항 등 자유 구조) |
| `tags` (text[]) | 자동 태그 |

이 값들은 `materials_export` 뷰에도 그대로 나오니, 다시 읽어 확인할 수 있습니다.
(원하면 운영팀 화면에서도 이 결과를 보여주도록 추가 가능 — 별도 작업.)

## 4. 추천 흐름 (에이전트 한 사이클)

1. `materials_export` 에서 `summary` 가 빈 자료를 조회 (= 아직 분석 안 됨)
2. `kind=file` → 2번으로 다운로드해 내용 읽기 / `kind=link` → URL 방문
3. 요약·QC·태그 생성
4. 3번으로 `materials` 에 PATCH
5. 반복

> 무료 우선 정책: 분석 LLM도 가능하면 무료 티어(Ollama 등) 먼저, 실패 시 유료 폴백 — 이 프로젝트의 기존 패턴과 동일하게.
